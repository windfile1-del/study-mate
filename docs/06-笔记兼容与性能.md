# 0.3.0 笔记兼容与性能

本阶段处理用户反馈：Obsidian知识库迁移后公式和流程图仍显示源码，切换大量笔记或浏览长文会卡顿。目标是尽量兼容Obsidian常用语法，同时保留原文件、避免主界面被排版阻塞。

## 已支持

| 内容 | 行为 |
| --- | --- |
| 数学 | $行内$、$$块级$$、分式、积分、矩阵、aligned/cases等KaTeX支持的命令，随包提供字体与CSS |
| Mermaid | 本地渲染流程图/时序图等支持的图种；长图可滚动，支持大图缩放和源码检查 |
| 双链 | [[笔记]]、[[目录/笔记#标题\|别名]]、[[笔记#^块标识]]；解析相对路径、根目录路径、唯一同名文件 |
| 图片 | Markdown相对图片、![[附件.svg\|620]]；PNG/JPEG/GIF/WebP/SVG/AVIF/BMP，HTTP(S)图片与常用base64图片 |
| 嵌入 | ![[笔记]]，一层嵌入，循环引用提示；标题定位可用 |
| Callout | [!tip]、[!warning]等类型，加粗标题、嵌套内容与+/-展开状态 |
| 其他 | YAML属性折叠查看、标题目录、表格、任务列表、高亮、注释、脚注和代码块原文 |
| 浏览 | 阅读/分栏/源码；默认打开笔记进入阅读，新建仍为分栏；Ctrl+S与原版本/备份机制保留 |

解释以上语法时不改写磁盘Markdown。源码和预览使用同一原文；只在保存时通过VaultService提交。

## 渲染链路

uiw编辑器负责源码编辑；阅读页复用unified/remark/rehype生态：

remark-parse → GFM/数学/frontmatter/Obsidian语法适配 → remark-rehype → HTML解析 → sanitize → KaTeX → HAST内容块。

HTML先净化，KaTeX使用trust:false、maxExpand限制。无效公式保留错误与源码，其余笔记继续显示。Mermaid使用strict模式，输出经DOMPurify清理后作为SVG图片展示；图内脚本/事件不作为界面运行，笔记内初始化配置不能降低应用配置。

实现依据：[remark-math/rehype-katex](https://github.com/remarkjs/remark-math)、[KaTeX选项](https://katex.org/docs/options)、[Mermaid API](https://mermaid.js.org/config/usage.html)、[TanStack Virtual](https://tanstack.com/virtual/latest/docs/introduction)。这些库随软件打包，不从CDN加载运行脚本和字体，不需要额外安装工具。

## 性能措施

- Markdown解析与全部公式排版在最多两个Web Worker中执行，快速切换会终止旧任务，不让过期结果覆盖新笔记。
- 超过60000字符时先解析首屏前缀，随后完成全文；前缀只在代码围栏与块公式之外截断。余文完成不把用户滚动位置重置到开头。
- 编辑同一笔记时保留上一次有效预览，后台完成后替换，避免每次按键把阅读区清空。
- 移除源位置字段，将后台结果以JSON文本传输，减少大量细粒度AST对象的结构化克隆开销。
- TanStack Virtual仅挂载可见内容及少量缓冲；超长列表/表格拆分为小块，图片进入视口附近才读取。
- 最近8份解析结果缓存，按序列化估算限制48MiB；图表另有32项缓存。阅读模式不挂载隐藏源码编辑器，大文档关闭源码语法着色。
- 知识库目录扫描复用Promise缓存；写入和Markdown变更才失效。文件监听忽略非Markdown文件，避免图片变化反复刷新整棵目录树。
- 文件名检索覆盖目录列表，优先快速匹配；正文按需读取最多前500篇的前64KB，分批并缓存，不在每次查询中读取全部长文件。
- 笔记加载/链接跳转使用代次检查；知识库切换期间显示状态，保持当前内容可读。
- Web Worker对实体解码、HTML解析明确使用不依赖DOM的包入口，避免浏览器条件导出调用document/DOMParser。
- 开发模式预先优化Worker使用的Markdown依赖，避免首次打开笔记触发Vite重新预构建并刷新整个界面。

## 本地图片与链接边界

新增study-note协议只在可信主界面会话注册。IPC显式携带vaultId；切库后的旧请求拒绝。图片只允许当前知识库内经过真实路径/符号链接检查的文件，每张上限20MiB；令牌跨知识库失效。外部file:与知识库外路径不会被当作授权附件。

重复文件名会先检查根/当前相对路径，其余搜索出现多义时要求补全目录。知识库图片和笔记嵌入不会通过路径联接读取库外内容。

## 验证与限制

核心测试32项，含语法、HTML脚本净化、无效公式、链接越界、目录缓存与块/脚注锚点。原生测试构建1204篇知识库和2200节含公式长文，验证范围包含：真实KaTeX、Mermaid SVG、相对图片、目录到文末、笔记嵌入、缓存返回和后台切换取消。

当前生产构建压力记录在artifacts/notes-smoke/result.json。一次通过记录：切库2071ms，首屏696ms，全文2582ms，缓存返回579ms；6600内容块仅挂载22块；25ms心跳P99为49.6ms、最大195.4ms。计时包含UI搜索/点击与等待，不是跨机器性能承诺；独立包记录另见artifacts/notes-packed/result.json。

同时通过独立D盘测试profile只读打开用户实际知识库的《函数性质关系》《二重积分做题方法详解》和deep-research-report，验证公式、Callout与实际流程图。三份原文件前后字节相同，未修改用户知识库。

边界：此版本不是Obsidian完整运行时；不运行Dataview/Templater/第三方插件，不直接编辑Excalidraw。KaTeX不覆盖所有MathJax扩展和跨笔记公式编号。嵌入最多一层、标题嵌入目前定位到该节而非精确截取该节。任务列表展示为只读，属性目前原样查看；没有宣称编辑器/工作区布局完全兼容。单笔记2MiB、目录深度16/最多5000篇仍为当前保护上限，正文搜索范围如上。大规模持续索引、10万文件和长时间内存压力未验收。

## 发布

新包放在release/0.3.0，不覆盖旧0.2.0目录；工程“启动工作台.cmd”优先新版，并沿用现有.local/data及知识库选择。直接解压包运行仍使用D:\StudyMateData默认数据目录，用户可选择已有知识库。

只在主进程运行时需要的chokidar、fuse.js、zod保留为生产依赖；React/编辑器/公式/图表等已经编译到out的库列为构建依赖，避免在app.asar重复携带整套源模块。独立验收会把运行目录复制到D:\StudyMateAcceptance的新临时目录，以该目录为cwd、PATH仅保留Windows系统目录，依次验证笔记和视频，成功后删除经过真实路径检查的临时副本。结果为artifacts/standalone/result.json，避免依赖解析意外回退到工程node_modules。

图表全屏窗口用React portal挂到document.body，避免虚拟滚动行的transform将fixed弹层限制在行内；自动化检查全窗口边界并容许不到1 CSS像素的DPI取整。
