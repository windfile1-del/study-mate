## 本次连接问题

实际 Wi-Fi：电脑 `192.168.1.5`，三星平板 `192.168.1.4`。电脑保存的监听网卡却是 VMware 的 `192.168.137.1`。用户在电脑连接面板切回 WLAN 后确认连接成功；不能把这次故障全部归因于 VPN。

电脑和平板都保留 VPN 开启。新增网卡排序优先 WLAN，虚拟网卡在界面明确标识；修正本机保存地址，启动器优先运行当前工程构建，避免启动缺少平板能力的旧发行版。未关闭 VPN、修改防火墙或强退用户的电脑实例。

Android 使用原 Wi-Fi 的 SocketFactory 和 NO_PROXY 访问已配对的局域网主机，TLS 证书固定与主机身份检查不变；没有放宽证书校验。Android VPN 的强制禁止绕过策略仍由系统执行，不能保证所有 VPN 配置均可用。依据：[Network SocketFactory](https://developer.android.com/reference/android/net/Network#getSocketFactory())、[VPN allowBypass](https://developer.android.com/reference/android/net/VpnService.Builder#allowBypass())。

服务发现采用每电脑身份唯一的名称，TXT 明确给出当前监听网卡地址，解决多网卡只解析出一个错误地址的情况。Android 顺序解析发现结果，重连失败时重新发现；端口改变后重新建立 HTTP/TLS/WSS 连接。发现信息只能更新地址，不能替换已配对证书。若路由器/VPN 阻断 mDNS，可在平板连接页手动更新 `IP:端口`。

## 缓存与恢复

- 近期笔记和对话使用 AndroidKeyStore AES-GCM 加密，按电脑、设备授权及知识库隔离。每个范围最多 12 篇笔记，逻辑 JSON 总量上限 2 MiB，单项超过 512 KiB 不缓存。没有缓存的内容仍需电脑；离线阅读明确标识，不能离线执行 AI 请求。
- 对话快照每 5 秒保存一次，已打开的笔记读取成功后保存。图片与笔记嵌入依赖电脑，未提供完整附件离线下载。重连更新客户端后重建阅读桥，重试断线期间失败的图片。
- Media3 使用应用私有目录中的 128 MiB LRU 视频缓冲。缓存键包含电脑、设备、知识库、来源、轨道和表示指纹；B站签名刷新可复用同一表示的缓存，画质/轨道路径变化会隔离，防止混用字节。电脑在准备本地媒体时再次核对文件版本，缓存不能绕过文件变化检查。只缓存已读取片段，未提供完整课程离线下载；视频缓存不包含模型密钥和平台 Cookie。
- 播放进度写入本机加密日志，向电脑保存成功后清除相应待同步项；重开课程时优先恢复尚未保存的本机位置。不会重放旧播放器会话的过期进度包。
- 不确定的提问保存原始 requestId、文本和冻结上下文，重启后只查询请求状态；需要用户明确点击才能查询/重试，不自动重复调用模型。
- 连接失效后退回缓存阅读，采用递增间隔重连；恢复前更新网卡和端口，访问令牌刷新后再升级 WSS。已知设备撤销或知识库授权失效时停止重连并清除对应缓存。新配对、清除配对及手动清缓存均有明确入口。

## 验收方式

`npm run smoke:android:stable` 使用独立 D 盘测试知识库和受控模型，保存并最终恢复平板原有配对；真实停止测试电脑服务 5 秒，并以新端口重新启动。平板必须先进入离线缓存阅读，再自动发现新端口恢复连接，随后执行阅读、图片/公式/图表、问答、播放器和进度接力回归。不会停止用户实际电脑服务。

`RecentCacheTest` 验证缓存对象重建、授权范围隔离、数量淘汰与清理；它不等同于真实设备掉电验证。所有 SDK、构建和测试暂存仍在 D 盘；不制作正式桌面发行包。长时间弱网、多 OEM、Android17 和完整离线课程不在当前短时故障注入的证据范围内。
