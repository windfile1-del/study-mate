# 会话与学习资料管理（0.13）

主界面沿用原有冷白青绿风格。本轮不要求下载新的本地模型。

## 自动引用资料

发送时自动附加当前可见工作台的引用：笔记路径、课件当前页码与选区、视频的课程编号和进度。打开但未显示的标签不自动参与；左右并排显示时，两边都会附加。隐藏右侧工作台后，其资料不再自动附加。两侧打开同一份课件也分别保留页码。

引用只是元数据，模型按需调用工具读取正文、字幕或图像。输入框不会展示内部工具指令。点击“看本页”产生的临时引用会在切换学习资料后清除；主动导入的图片引用可手动移除。

## 会话与累计消耗

助手上方有会话标签和历史管理入口，可新建、切换、搜索、重命名及删除历史会话。旧版本的本地归档会迁入列表。每个会话分别保留消息、压缩记忆与输入草稿；生成或压缩中需先结束或停止，再切换会话。

意外中断后保留已经收到的回答，标注中断；没有确认结果的工具不会显示为保存成功。恢复会话时如果摘要的覆盖边界与原始消息不一致，会舍弃失效摘要并保留原始记录。

用量显示当前会话累计和全部会话累计，分别列出主模型、视觉和压缩消耗，压缩或删除历史不会让全局累计归零。显示的是服务商已经返回的指标，未返回时会标记；旧版未记录的早期压缩费用无法凭空补回。上下文占用仍单独显示最近一次请求的窗口占用，它与累计消耗是两个概念。

## 资料与备份管理

左侧“资料与备份管理”提供笔记、PDF/PPT、课程、备份和最近学习分类；笔记工具栏也有当前笔记备份入口。

备份的实际路径会显示在页面顶部：通常为应用数据目录下 `state/backups/<知识库ID>`。工程启动器使用 `D:\study-mate\.local\data`；独立便携程序默认使用 `D:\StudyMateData`。新备份记录原笔记路径、时间和版本，可预览、恢复及清理选中版本。旧版仅有内容哈希的备份不能可靠猜测原路径，恢复时需明确指定相对路径。

恢复前会备份当前版本，磁盘版本冲突或存在未保存草稿时拒绝覆盖。笔记删除会先备份，再移入系统回收站。课件和课程移除只移除软件内记录，保留原始文件。备份清理只作用于选中的应用备份，不会清理当前笔记或用户原文件。

## 滚动、听写与缓存

Markdown 的源码、分栏和阅读视图共享阅读进度；分栏时双向同步滚动，进度保存在本地，切换视图或重新打开时恢复。长文仍按可见块渲染。

播放器旁的“音频转文字”独立于字幕开关，默认识别中文。前者采集课程音轨生成可检索文本，后者控制已有字幕显示。暂停、倍速与跳转的原视频时间映射沿用已验证的识别引擎。

缓存保留时长可设 1–24 小时，检查频率可设至每 24 小时。检查不会无条件删除整堂课；应用运行时会在缓存到期时安排清理，退出期间的到期缓存会在下次启动清理。超出空间上限仍可能按最旧画面淘汰。长课程提高了单课帧容量，整体空间预算也可调整。仅清理自动帧，字幕、转写、原视频和笔记不会随之删除。

## 找回上一节课

应用保存最近访问课程的时间、进度和观看区间。询问“上一节课的传递函数定义”时，先依据当前是否正在观看课程选取前一门或最近学习的课程，先检索字幕和转写，再查看命中时间的真实画面。缺少文字证据时，先从观看范围分散读取少量关键帧粗定位，再细看相关片段；无法可靠定位才询问大致时间。旧版缺少观看进度的课程只按最后打开时间推断，并保留不确定提示。

## 压缩与缓存

本轮参考 [Codex 代理循环与缓存、压缩设计](https://openai.com/index/unrolling-the-codex-agent-loop/)、[OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction)、[OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching)、[Claude Code 成本与上下文管理](https://code.claude.com/docs/en/costs) 和 [Claude Compaction](https://platform.claude.com/docs/en/build-with-claude/compaction)。

采用适用于多种接口的增量摘要：保留最近完整轮次，按目标/约束、公式数值、来源与保存结果、未完成问题组织较早记录；补充原始用户线索和有界工具结果摘录，原始消息不删，模型可按需检索原始消息与工具返回，找回正文尾部的精确公式。图像像素和原生推理签名不加入文字检索。摘要分段追加，只在需要时合并，避免每轮重写全部记忆；自动压缩设置滞回，减少频繁压缩。压缩失败或摘要没有缩小时保留原上下文。

固定指令和工具定义保持稳定，动态资料放在本轮消息尾部。Claude 的系统提示有独立缓存断点；官方 OpenAI API 使用稳定会话缓存键。这里没有把明文摘要冒充供应商的不透明压缩项，也不重写原生推理签名。压缩必然可能改变历史缓存前缀，首轮重新预热不能完全避免；应结合输入总量和实际返回命中指标评估，不承诺固定命中率。

## 验证方式

本轮按改动依赖验证，不重复此前未受影响的 ASR 模型、账号登录、文档底层绘制和数学渲染验收。成功检查记录源文件依赖指纹；同一检查仅在依赖或测试本身变化后重跑。用受控接口验证真实传输与工具执行，不能据此宣称真实模型的语义理解、账单或供应商缓存效果已经验收。

工程内运行 `npm run test:workflow`、`npm run test:affected` 和 `npm run smoke:workflow` 可按记录选择需要重跑的检查。记录在 `artifacts/0.13`；未变化的成功检查打印 reused，不会重新打开软件或重复识别样本。
