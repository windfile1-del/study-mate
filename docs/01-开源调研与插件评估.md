r2补充：笔记改为直接集成 @uiw/react-md-editor、react-arborist、chokidar 等成熟组件；具体比较、授权核对和精简排期见 [04 开源笔记复用与精简排期](04-开源笔记复用与精简排期.md)。

## 1. 调研结论

推荐自行构建轻量桌面宿主，复用现有插件的观察和时间轴能力。其他项目分别提供采集、转录、时间对齐、知识组织和 Agent 交互参考。

本轮检查的项目中，没有一个已被本轮运行验证为同时满足“应用内浏览器 + 与正在播放进度同步 + 独立回看 + 本地 Markdown 文件库 + Agent 持续维护”。这只是本次调研范围内的结论，不等于 GitHub 上不存在其他实现。

选型次序：

1. 自有插件作为观察引擎起点。
2. Prismical 参考 Electron、后台采音和转录任务的工程组织。
3. 小型 VideoRAG 参考同一视频内的语音片段与关键帧对齐。
4. Open Notebook 参考来源、笔记、对话分离，以及上下文范围控制。
5. BiliNote 参考视频笔记、来源跳转和模型就绪引导。
6. Chalk 参考画面去重与崩溃恢复思想，暂不直接搬运其代码。

### 对调研结果的取舍

不把数个现有产品代码拼接为一个应用：数据库、运行时、笔记格式和会话模型的差异，会把整合成本变成长期负担。

优先直接使用独立组件，参考产品的设计：

| 能力 | 首选组件 | 选择理由 / 本轮依据 |
| --- | --- | --- |
| 桌面/网页宿主 | Electron 的 WebContentsView | [官方 API](https://www.electronjs.org/docs/latest/api/web-contents-view) 支持独立网页视图；便于迁移现有 Node.js 观察核心 |
| Markdown 编辑与预览 | [@uiw/react-md-editor](https://github.com/uiwjs/react-md-editor) | 直接复用React编辑器、工具栏和预览，接本地读写；不从CodeMirror起自行搭建完整编辑界面 |
| Markdown 公式等扩展 | 编辑器现成预览插件 + KaTeX | 按官方示例集成；已有笔记原文保真与安全渲染仍需验证 |
| 文件树与文件监听 | [react-arborist](https://github.com/jameskerr/react-arborist) + [chokidar](https://github.com/paulmillr/chokidar) | 直接复用UI和监听能力，真实文件操作由受限文件服务处理；均已核对MIT |
| PDF | PDF.js | [官方仓库](https://github.com/mozilla/pdf.js)，Apache-2.0；用页面/选区提供可定位上下文 |
| 索引 | SQLite + FTS5 | [官方 FTS5 文档](https://www.sqlite.org/fts5.html)；单机使用无需单独数据库服务 |
| 工具调用/模型适配 | Vercel AI SDK 的受控封装 | [官方工具调用文档](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling)，仓库 LICENSE 为 Apache-2.0；应用自己管理权限、预算、证据与写入事务 |
| 本地转录 | whisper.cpp 独立进程 | [官方仓库](https://github.com/ggml-org/whisper.cpp)，MIT；模型按需下载，P5 验证中文精度与运行速度 |
| 媒体抽取 | FFmpeg；在线解析可选 yt-dlp | 延续现有媒体回填设计；[yt-dlp 官方仓库](https://github.com/yt-dlp/yt-dlp)，[FFmpeg 许可](https://ffmpeg.org/legal.html) 随构建选项变化，现插件自带 exe 不能未经核对直接成为新安装包的发行组件 |

以上组件的具体版本在 P0 锁定并记录，避免将文档的“latest”当成可重现依赖。首版不要求 Docker、SurrealDB、Qdrant 服务或 Python 全家桶。

## 5. 源码中需要解决的问题

### P0：身份、证据与隔离

1. **场景特征缺失。** page-observer 没有计算 hash/pixels 等比较特征；缺少哈希时 hammingDistance 返回 1，SceneDetector 会判定切换。本轮以三个相同占位帧、时间 0/15/30 秒复现，scene 分别为 1/2/3，sceneCut 均为 true。
2. **不能只给页面增加 hash。** BrowserAdapter.normalizeFrame 和 FrameCapture.validateFrame 没有保留顶层 hash/pixels。本轮也验证归一化后这两个字段为空。新特征必须进入版本化合约，并贯穿采集、校验、持久化和比较；特征缺失应返回 unknown。
3. **单个活动 session 不适合桌面多标签页。** TemporalIndex 用 currentSessionId，字幕默认写当前 session；现有可见字幕上报没有明确 source/visit/generation。并发、导航和延迟回调可能把证据关联错对象，需显式绑定目标。
4. **分 P 与 cid 混用。** extractVideoId 把 URL 的 p 或 cid 都放入 cid。p=2 是分 P 序号，不是真实内容 cid。新应用分别存 platformVideoId、partIndex、platformContentId，未拿到真实 cid 时使用明确的临时身份。
5. **没有已观看区间模型。** 现有快照包含播放时间，但不足以表达跳转、倍速、暂停及回看。300 秒环形缓存按媒体时间裁剪也不能代替按实际观察时间维护的热缓存。

### P1：持久化、内容覆盖与资源

6. **持久策略需要按产品重做。** 现默认落 os.tmpdir，且系统重启会清缓存；产品应长期保留已选择课程。FrameArchive 已有 clearOnReboot 构造选项，可以在新适配层显式关闭，避免沿用默认行为。
7. **内存放大出现在整 session hydrate。** initialize 已通过 includeData:false 恢复元数据，并不是启动时把所有图片读为 Base64；但 hydrateArchive 会整 session 加载图像，新观看 archiveFrames 也保留 data。应改按区间取有限帧、文件引用与 LRU。
8. **OCR 目前是字段与索引入口。** 本轮未见执行 OCR 的完整工作模块；可见字幕由页面 DOM 采样并估算结束时间，不等同于完整字幕轨，更不等同于无字幕课程的 ASR。
9. **高清帧持久化链不完整。** addHqFrame/ingestBackfillFrames 保留内存帧，saveSession 会剥离 data；本轮所读的回填路径没有调用 archiveFrame(..., "hq") 写入像素文件。新产品需要让高清像素和引用一起可恢复。
10. **采样计划没有驱动前端频率。** AdaptiveSampler 的 0.5/1/2/6 数值是规划结果，页面仍按 10–20 秒归档；新产品需把轻量变化检测、正式归档和模型发送三种频率分开。
11. **启动器偏一次性注入。** 当前通过 Runtime.evaluate 注入；普通整页导航后的持续重挂接、iframe 和播放器重建必须交由桌面宿主生命周期处理，不能假设变量永久存在。
12. **HTTP 桥接缺少上报身份。** 当前 loopback 服务允许通配 CORS、无独立上报令牌。桌面内部用有 sender/source 校验的窄 IPC；未来扩展桥接才设计配对与令牌。

这些问题不否定原插件已完成的工作流验证；它们界定了“能用于个人插件”到“能长期稳定运行的桌面应用”之间的迁移工作。

## 7. 复用实施方法

新项目采用“固定来源版本 → 提取小模块和相应测试 → 建立本地合约 → 替换传输/存储 → 验证真实输入”的顺序。

第一次提取时保留来源说明、版权与原始版本记录。先允许已有 .mjs 模块被 TypeScript 外层包装，避免一开始同时重写语言、存储和算法。新旧插件不共享正在写入的缓存目录，也不在迁移时批量删除原归档。

外部开源项目先参考设计；只有确认具体文件与依赖适配、实际需要复用时，才把代码及其许可证纳入项目。
