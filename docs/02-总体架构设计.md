# Study Mate 总体架构设计

日期：2026-10-25。性质：拟实施架构，不代表当前已有软件功能。

r2执行说明：首先按 [开源笔记复用与精简排期](04-开源笔记复用与精简排期.md) 交付。编辑/预览、目录树和监听直接集成现成组件；先沿用插件观察模块与文件归档。下文的完整SQLite表、独立Worker细分和高级索引是演进目标，不要求首版全部建立。

## 1. 产品边界与关键决策

首版是一款 Windows 学习工作台：左侧知识库，中间浏览器/本地视频/PDF/笔记标签页，右侧伴学对话。AI 访问经过索引的课程证据和用户授予的知识库，能够按明确指令创建和修改笔记。

| 决策 | 推荐方案 | 主要原因 |
| --- | --- | --- |
| 桌面宿主 | Electron + WebContentsView | 迁移现有 Node.js 核心成本较低，并具备受控网页生命周期 |
| 界面 | React + TypeScript；分栏可调整 | 知识库、阅读与问答可同时使用 |
| 工程工具 | pnpm workspace + electron-vite；electron-builder 稳定版 | 统一 main/preload/renderer 构建；先验证 Windows 原生依赖再锁版本 |
| 应用形态 | 一个桌面应用，内部模块化，重任务独立进程 | 避免首版引入本地 Web 服务群和复杂部署 |
| 笔记真源 | 本地 .md 与附件目录 | 保持与 Obsidian 及普通编辑器兼容 |
| 笔记界面 | @uiw/react-md-editor + react-arborist | 直接复用编辑、预览、工具栏与目录树 |
| 学习索引 | 首版沿用文件归档；后续SQLite WAL + FTS5 | 避免为首次交付全面重写存储，保持图片/音频独立文件 |
| 模型 | 用户自配提供商；能力探测与适配层 | 不绑定某一模型、云账户或 Codex 桌面端 |
| AI Runtime | 有预算的单 Agent 工具循环 | 学习解释与笔记维护无需先引入多 Agent 编排 |
| 视频观察 | 前台只读、缓存检索、独立媒体回填 | AI 不通过拖动用户播放器取得上下文 |
| 音频 | 字幕优先，指定网页采音次之；本地媒体独立解码 | 无字幕课程有补充路径，尽量避免整机声音混入 |
| 可扩展性 | 平台适配器、ProviderAdapter、EvidenceRepository | 后续扩展网站、模型、检索能力，不把未来平台当首版约束 |

Electron [WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view) 是本方案的宿主基础。构建参考 [electron-vite](https://electron-vite.org/guide/)；打包按 [electron-builder](https://www.electron.build/) 指向的稳定版文档锁定，不跟随文档站的未发布版本。

首版不做跨设备同步、Android 客户端、公共账号系统、通用自动化浏览器、多 Agent 团队或完整 Obsidian 插件兼容层。相关扩展有清晰接口，不阻塞首版交付。

## 2. 用户工作流与界面

### 2.1 学习工作台

- 左栏：知识库文件树、课程来源、搜索、最近笔记；允许收起。
- 中栏：浏览器地址栏与标签页、本地播放器、PDF 页码/缩放、Markdown 编辑与预览。
- 右栏：对话、当前绑定来源、回答引用、工具活动、笔记变更与撤销。
- 阅读区底部：观察状态、语音/字幕状态、最新证据时间和缓存占用；状态不正常时直接写明原因。

首启只完成三件事：选择 D 盘数据目录、打开/新建知识库、配置一个模型连接。模型配置提供名称、接口地址、密钥、模型名和连接测试；密钥支持掩码，错误紧邻字段。高级网络和上下文预算默认折叠。

“正在学习的来源”和“当前对话绑定的来源”分别显示。新问题默认使用当前阅读对象；用户固定某门课程后，对话不会被其他标签页自动改绑。

### 2.2 “解释刚才老师讲的内容”

1. 用户在 18:42 发问。
2. 提交瞬间冻结来源、播放位置、观察代次、最近观看区间和 PDF/笔记选区。
3. 应用立即展示“基于某课程 18:42 附近”，随后检索冻结范围中的字幕、画面与已完成转录。
4. AI 先读紧凑证据，细节不够时申请指定时间高清帧或 PDF 局部图像。
5. 回答附可点开的时间戳、证据预览和缺失说明。用户继续播放不影响这条问题的目标。

点击“展开来源”只展示缓存/局部阅读器，不自动改变播放器。只有用户主动点击“跳转到原视频”才允许 seek，这个交互走用户操作通道，不属于 Agent 的可调用工具。

### 2.3 “整理笔记保存下来”

用户明确要求保存后，AI 创建普通 Markdown 文件；用户已授权知识库内的新建无需再弹一次确认。创建结果显示实际路径、来源链接与撤销入口。

对明确指定的已有笔记，按用户指令生成补丁并在版本检查通过后写入、保留备份。未明确目标且存在多个候选时先生成独立草稿，或在界面选择目标。已有文件有外部修改冲突时暂停该次写入，让用户比较差异。

### 2.4 PDF 与现有笔记

打开 PDF 后，AI 默认只获得当前页/选区和少量相关页面，不把整本书发送给模型。笔记问答默认限定当前知识库，用户可以指定文件或课程范围。

Markdown 保存保留 frontmatter、链接、代码块、公式、换行风格及用户原始格式；应用不先转成富文本再覆盖原文件。

| 运行位置 | 职责 | 不承担的工作 |
| --- | --- | --- |
| Electron main | 来源/窗口注册、sender 校验、工具授权、队列路由、子进程回收 | OCR、语音推理、全库扫描、同步大查询 |
| 可信应用 renderer | UI、现成Markdown编辑器、PDF.js、用户发起的 Web API 采音 | 任意 Node/文件系统访问 |
| 远程 WebContentsView | 网站本身与隔离 preload 的只读采集 | 本地文件、模型密钥、任意 IPC 调用 |
| 数据/Agent utility worker | SQLite、检索、ProviderAdapter、工具计划 | 绕过主进程的权限边界 |
| media 子进程 | 限并发的解码、ASR、后续 OCR | 用户播放器控制、无限下载 |
| VaultService | 受授权根目录限制的笔记读写和备份 | 无界目录访问或任意 shell |

重任务分进程能改善故障隔离，但不是权限沙箱本身；ToolBroker 和文件服务仍逐次校验范围。

浏览器采用独立的持久 session partition 保存用户正常登录态。观察器不导出 Cookie/Token，也不默认把浏览器凭据交给 yt-dlp、模型或外部插件。

主窗口的网页子视图使用原生视图层：分栏缩放、DPI、弹窗和遮挡由主进程同步 bounds。应用级模态框打开时隐藏相应网页视图，避免把 DOM z-index 当作跨原生视图的遮罩。关闭标签页时销毁对应 webContents 和观察资源。

## 4. 浏览器与平台适配

### 4.1 两层适配器

SourceAdapter：统一生命周期、来源身份、当前定位、能力状态与证据事件。

VideoAdapter：视频元素选择、媒体时钟、分 P、字幕与帧读取。首版实现 BilibiliAdapter 和 LocalVideoAdapter；GenericHtmlVideoAdapter 放到后续通用网页阶段。

适配器必须公布能力：可否读进度、帧、字幕、音频、独立回填，以及失败原因。支持播放不等于支持每种观察能力。

### 4.2 网页挂接

受控 preload 在隔离世界中观察 DOM 和播放器事件，不向网页暴露 ipcRenderer、文件工具或任意 execute 接口。主进程记录 webContentsId、frame 和来源注册关系，忽略网页自报的授权范围。

处理整页导航、SPA 导航、分 P 切换、video 节点替换、播放器尚未就绪、iframe 和多 video。每次导航/重绑递增 generation；旧回调即使晚到，也不能写入新来源。

首版默认一个活动课程来源。多个标签页可保留，但不同时给所有页面做重采样；切换观察目标由用户操作触发，并显示当前目标。

### 4.3 采帧优先级

1. 对支持的 HTML video 执行 Canvas 只读复制。
2. Canvas 失败时尝试 [webContents.capturePage](https://www.electronjs.org/docs/latest/api/web-contents#contentscapturepagerect-opts) 并按视频区域裁剪；裁剪坐标、滚动、DPI、可见性都参与验证。
3. 已缓存帧不能看清时，单独媒体进程按指定时间解码；网络源解析失败就保留清楚的 unsupported/permission-required/metadata-only 状态。

浏览器裁剪图会包含播放器叠层，证据必须标记 browser-crop。隐藏/最小化、受保护内容、跨域画布和黑帧需要真实页面验证；不通过关闭 webSecurity 来解决采集失败。

### 4.4 音频采集的可行路线

首选现有字幕，其次用户主动开启指定网页音频采集。Electron 当前 [session API](https://www.electronjs.org/docs/latest/api/session#sessetdisplaymediarequesthandlerhandler-opts) 支持以目标 WebFrameMain 作为音频来源，并以 enableLocalEcho 保留本地声音。

设计上由可信应用界面在用户真实点击后请求 getDisplayMedia；主进程只为该可信请求授予已选择来源的 mainFrame，不能把 request.frame 不加检查地当成授权目标。传入 frame 实际捕获的是它所属的整个 webContents。采集后的 PCM/音频分块在 Web Worker / media-worker 处理。

这只是官方接口支持的方案，仍须在选定 Electron 版本、Windows 和 B站真实课程中验证：音频可听、不重复、不静音、不混其他标签页，拖动/倍速后可对齐。

本地视频直接由 FFmpeg 读取原文件音频，与前台播放器分开。整机 loopback 仅作为用户明确选择的降级方式，界面注明会混入其他应用声音；不能静默切换。若指定来源捕获失败，保留字幕/画面模式。

## 5. 时间轴和身份模型

### 5.1 四个身份层次

| 对象 | 含义 | 示例与约束 |
| --- | --- | --- |
| workspaceId | 一个学习项目及其授权知识库 | 跨课程搜索也必须显式限定 workspace |
| sourceId | 稳定的学习来源 | B站 BV+分 P/真实 cid、本地媒体、PDF；数据库使用独立内部 ID |
| visitId | 某个标签页/阅读器的一次观察会话 | 同一视频的两个标签页也不同 |
| generation / playbackEpoch | 导航代次 / 连续播放时段 | seek、切来源、异常时间跳变时关闭旧时段 |

B站存 platformVideoId、partIndex、platformContentId；partIndex 不冒充 cid。只知道 BV+p 时可以建立 provisional canonicalKey，拿到真实 cid 后通过别名映射合并，保留引用，不能靠改主键丢历史。

本地文件登记路径、文件身份、大小、修改时间与轻量指纹；移动文件可重新定位，文件内容变化形成新 revision，不能把同路径的新课程当旧证据。PDF 页码同样绑定文档 revision。

### 5.2 三种时间

- mediaTime：视频自身的秒数或 PDF 页码等定位。
- observedAt：UTC 时间，用于用户记录和审计。
- observedMono：通过时钟锚点映射的单调时间，用于音频、媒体进度与事件对齐。

不同 renderer/worker 的单调时钟不能直接比较。主进程维护各发送方 clockId 的锚点与往返测量误差；音频 sample offset 映射回同一单调参考，再关联播放器锚点。

连续播放时可按起点、终点与实际倍速分段映射。暂停、seek、ratechange、卡顿、休眠或长时间丢报时关闭片段，不能用“初始播放时间 + 录制总时长”解释整段音频。

### 5.3 已观看区间与证据覆盖分开

watched_intervals 记录确认实际连续播放的媒体区间；心跳、paused、rate、seeking 和不连续事件共同判断。长时间断连不能凭前后两个点推定中间都已观看。

证据覆盖分别记录：

- 画面采样时间点与最大间隔；
- 字幕/转录的起止和缺口；
- 实际观看区间；
- 独立回填的片段及其时间。

看过某段不代表每一秒有图像；回填到未来画面也不代表用户已经学过。默认当前问答不越过发送时刻的进度，整课概览则明确使用完整来源。

### 5.4 不可变的问答上下文

~~~typescript
type ContextAnchor = {
  workspaceId: string;
  chatId: string;
  requestId: string;
  sourceId: string;
  sourceRevision: string;
  visitId?: string;
  generation?: number;
  playbackEpoch?: number;
  mediaTime?: number;
  pdfPage?: number;
  selection?: { text: string; locatorId: string };
  submittedAt: string;
  evidenceCutoffAt: string;
};
~~~

所有工具调用传入 requestId 和 sourceId；服务端从 requestId 查冻结上下文，不临时读取全局 activeSource。历史课程查找显式指定 sourceId。回填完成时再次校验目标和代次，不能把返回结果写入当前打开的视频。

当前状态超过约 3.5 秒未更新就标记 stale；可以回答已有历史证据，但不得把最后记录的位置声称为实时位置。

## 6. 采样、归档与内容管线

### 6.1 初始参数

下列是拟定默认值，需要通过 P0 和性能验收调校。

| 管线 | 初始策略 |
| --- | --- |
| 播放器状态 | 约 1 秒一次，关键播放器事件立即上报 |
| 低成本变化检测 | 活跃播放时约 2 秒一次，只计算缩小的灰度特征 |
| 常规低清归档 | 约 15 秒一次，最高 960×540 WebP |
| 变化触发归档 | 明显变化时额外留帧，设置最小间隔和每分钟上限 |
| 当前问题补帧 | 请求时读取当前帧；历史细节只从缓存或独立解码获取 |
| OCR | 新关键帧或用户请求时执行，不对每秒快照运行 |
| ASR | 约 20–30 秒分块，保留少量重叠并按媒体时间去重 |
| 送入模型 | 一次先取约 4–6 张帧和相关文本，默认最多 8 张；必要时下一步补充 |

轻量特征计算失败时记录 unknown；不将其当作“场景变化为真”。同一内容去重只减少存储/模型输入，保留观测时间与来源覆盖元数据。

常规采集不会自动发送给大模型。用户提问或明确开启自动笔记任务时，才按预算使用模型。

### 6.2 数据写入

观察事件带 schemaVersion、visitId、generation、seq、时钟信息与载荷；主进程绑定实际 sourceId，验证大小、类型、顺序和能力。

帧采用二进制或文件句柄引用，避免跨 IPC 长期传递 Base64。旧插件兼容入口在边界解码一次。

新帧先写到同目录临时文件并完成 rename，再提交数据库元数据和索引事务；崩溃恢复时清理未引用孤立文件。任务和写入均有幂等键，例如 source/revision/mediaTime/quality/算法版本。源数据删除与清理事务采用 tombstone/任务恢复，不假设文件系统与 SQLite 是同一原子事务。

### 6.3 字幕、ASR 与 OCR

字幕按来源保留 original-track、visible-dom、imported-srt/vtt、local-asr 等标记。当前插件可见 DOM 字幕的估计时段不能升级成高精度原始字幕轨。

whisper.cpp 使用多语种模型，中文课程不能选只支持英文的 .en 模型。默认模型按需下载到 D 盘，先验证 CPU 运行；GPU 加速是后续可选能力。原始语音识别文本可人工修正，修正与自动结果分别保存。

一块音频记录 sourceId、visitId、epoch、媒体起止、采样率、单调时间锚点、处理状态和误差估计。seek 时丢弃/封口跨界尾部，不能把旧音频拼到新进度。倍速导致的语音识别质量与对齐单独验收。

OCR 第一阶段可用已支持中文的独立引擎或 Windows OCR 适配器进行 P5 比较；普通文字与公式分开处理。公式/板书不确定时优先给模型原图或局部高清图，不能把错误 OCR 当作确定的公式。

## 7. 统一学习上下文与检索

LearningContextService 将视频、PDF 和笔记统一为 EvidencePacket。

~~~typescript
type EvidencePacket = {
  requestId: string;
  sourceId: string;
  sourceRevision: string;
  scope: { start?: number; end?: number; page?: number };
  frames: Array<{
    evidenceId: string;
    mediaTime: number;
    assetId: string;
    width: number;
    height: number;
    quality: "preview" | "hq";
    origin: "canvas" | "browser-crop" | "ffmpeg";
  }>;
  text: Array<{
    evidenceId: string;
    text: string;
    start?: number;
    end?: number;
    page?: number;
    origin: "subtitle-track" | "visible-dom" | "asr" | "ocr" | "pdf" | "note";
  }>;
  gaps: Array<{ reason: string; start?: number; end?: number }>;
  stale: boolean;
};
~~~

检索顺序：

1. 按冻结来源和时间/页码取附近证据。
2. 用问题在同一来源字幕、转录、OCR、PDF 文本中搜索。
3. 将命中文本与同来源、相近时间的帧或同页选区配对。
4. 去重并保留前后必要上下文，受帧数/字数/模型预算限制。
5. 不够时才调用独立回填或扩大范围；每次扩大都保持来源约束。

“刚才”优先解释最近实际观看的一段内容；发生跳转时按实际观看片段取证，不能简单把所有 [t-90,t] 都当刚刚看过。通用知识可以补充，但回答中区分课程证据与模型解释。

首版对小规模知识库使用Fuse.js和受范围/大小限制的中文子串匹配，复用现有视频文本查询。数据增长后引入SQLite全文检索，再考虑embedding。FTS5默认unicode61不等于中文分词；后续可采用中文分词后的检索文本或trigram索引。按 [FTS5 官方限制](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)，不足三个字符的查询仍须额外处理。中文双字与“PID”“ζ”属于各阶段实际查询验收样例。

向量索引为可重建派生数据，键包含 embeddingProvider/model/dimension/version，不能混用不同模型的向量。首版不部署单独向量数据库。

## 8. Agent Runtime 与工具

### 8.1 模型适配

ProviderAdapter 提供流式文本、图片输入、工具调用、取消、用量与错误映射。配置界面分别测试文字、视觉和工具能力，不把接口能返回一句话当作全部功能可用。

Vercel AI SDK 负责协议适配与受控工具循环的基础能力；应用自己控制上下文冻结、工具权限、来源、幂等和预算。参考 [官方工具调用](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling)，但不在业务代码中传播易变 SDK 类型，锁版本后再按对应 API 实现。

无视觉能力时可以解释字幕/PDF 文本，界面明确“当前模型无法看图”；无工具能力时可提供问答和可手动保存草稿。离线时保留阅读、编辑、缓存与本地转录，云模型问答进入可恢复的未发送状态。

### 8.2 工具面

| 工具 | 用途与关键参数 |
| --- | --- |
| get_learning_context | requestId 对应冻结上下文；有限 time/page 范围 |
| search_source | sourceId/revision/query；不能默认扩大到其他课程 |
| inspect_frames | evidenceIds 或 sourceId + 时间；preview 优先 |
| request_media_backfill | 固定 sourceId/revision/时间、limit、budget、taskId |
| read_pdf_region | 文档 revision、页码、bbox 或选区 |
| list_notes / search_notes / read_note | workspace 和知识库内路径/文档 ID |
| create_note | 指定目录、Markdown、幂等键、引用附件 |
| patch_note | 路径、baseVersion、补丁、操作 ID |
| attach_asset | 复制已批准证据到笔记附件目录，返回普通相对链接 |

默认不提供任意 shell、任意路径写入或播放器 seek 工具。工具结果大小有上限，失败可识别为暂时、权限、来源不存在、版本冲突或不支持。

每条请求初始最多约 8 个工具步骤、一个用户可见的整体截止时间和可调 token/image 预算。只读查询可按退避策略重试；已发生的写操作依靠 operationId 查结果，不能因网络断线重复创建同一篇笔记。

流式对话中的“取消”同时中止网络请求、排队任务和子进程；已经提交成功的笔记保留并显示结果，可撤销。重启后未完成运行显示 interrupted，不悄悄重放写操作。

## 9. Markdown Vault 与 PDF

### 9.1 文件与索引关系

.md文件是笔记真源；首版用文件元数据/操作记录与小规模搜索，后续SQLite只存派生索引、版本、链接和来源。外部Obsidian修改由chokidar与启动时增量扫描同步；监听去抖、改名识别和自写事件抑制，不能形成读写循环。

编辑器未保存草稿、磁盘版本、AI 编辑版本分别保存。AI 写入必须基于 baseVersion 比较；有差异时返回 conflict，不覆盖外部编辑。

写入流程：路径校验 → 读当前版本 → 校验 baseVersion → 创建备份/操作日志 → 同目录临时文件 → 原子替换 → 确认磁盘结果 → 更新索引。Windows 文件锁只做有限重试，失败后保留草稿和明确恢复入口。

校验使用实际授权根目录、realpath/祖先关系和 Windows 大小写规则；拒绝 .. 越界、保留设备名、替代数据流和子目录 reparse/junction 跳转。写入前再次校验目标父目录，避免把纯字符串前缀当成目录授权。

### 9.2 兼容范围

第一版复用现成编辑器支持标准Markdown、代码块、表格、相对图片和公式扩展。frontmatter及未知特殊语法按原文保存，预览可降级；完整wikilink解析、反向链接和知识图谱后续增加，不作为首次交付门槛。编辑器通过字符串值接文件服务，未编辑文件不自动格式化保存。

笔记含普通来源链接：B站 URL 保留 BV/分 P/时间信息；PDF 使用相对文件链接和页码。应用内部额外记录结构化 locator；应用不在运行时也能阅读笔记正文。

用户把课程图像插入笔记时，复制到知识库附件目录。之后清空视频缓存不会删除笔记中的图片。缓存目录中的路径不直接成为长期笔记附件引用。

### 9.3 PDF 服务

PDF.js 负责阅读、选区和页面文本提取，页面文本按 document revision/page 存索引。大文件只渲染附近页面；取消过期渲染，避免整本书同时转图片。

扫描页无文本时按需 OCR/视觉模型，带页码/区域/来源标记；有密码、损坏或超大文件时显示具体状态，不把空文本当作成功提取。

## 11. 缓存、预算与可靠性

### 11.1 保留规则

应用缓存与笔记附件分开。课程记录和笔记来源不因重启消失；图像/音频可按配额清理，清理后引用显示“缓存已清除，可尝试重新提取”。

初始可配置上限 5 GiB，磁盘剩余空间不足时停止重任务、提示清理。正在运行任务引用的资源、用户固定课程和笔记附件不能被普通 LRU 清理。清空课程缓存与删除用户笔记是独立操作。

内存只保留有限元数据、当前/近期图片和任务缓冲；热缓存按实际观测顺序 + 字节数淘汰，媒体时间检索走数据库，解决回看/跳转乱序。

### 11.2 容量估算

以下为设计估算，不是本机测量：

- 每 15 秒一帧即每小时 240 帧；若单帧 40–150 KiB，约 10–36 MiB/小时，不含额外关键帧和高清图。
- 16 kHz、16 bit、单声道 PCM 约 110 MiB/小时；32 kbit/s 压缩音频约 14 MiB/小时。是否保留原音频由用户选择。
- 模型按图片/文本预算计量，不能把归档帧数等同于每小时模型调用量。具体费用在选定供应商后显示真实用量，不在本方案固定价格。

### 11.3 队列与恢复

优先级：用户当前问答 > 当前状态更新 > 持续采集 > 后台转录/全文索引 > 全课回填。

初始 FFmpeg 回填并发 1，ASR 推理并发 1。队列满时允许丢弃过期低优先级采样，必须记录缺口；写笔记等有副作用操作不能静默丢弃。

任务状态为 queued/running/succeeded/failed/cancelled/interrupted；持久化进度与目标，崩溃后只恢复可安全重试的读/计算任务。日志记录 sourceId/requestId/taskId、错误类型和耗时，不默认记录密钥、完整对话或原始二进制。

## 12. 边界与后续扩展

远程网页始终 nodeIntegration:false、contextIsolation:true、sandbox:true，保持 webSecurity；IPC 校验发送者和允许操作。依据 [Electron 官方安全文档](https://github.com/electron/electron/blob/main/docs/tutorial/security.md)。页面文字、字幕、PDF 和模型输出均作为数据，不作为授权指令。

本期内部不开放通配 CORS 的本地 HTTP 服务。未来浏览器扩展接入需要用户配对、随机令牌、来源校验、请求限流；MCP 默认关闭，明确开启后复用同一 ToolBroker。

未来按顺序扩展：语义检索和跨课程关联 → 更多网站适配器 → 外部浏览器扩展/MCP → 其他桌面平台。Android 需要新的浏览器/捕获和文件适配层，不能把 Electron 安装包直接转为 Android 应用。
